# 回溯性重构 · dsh-retro

## 一句话

**它是一个 DSH 插件。写记忆的时候，它只检查一件事：这条有没有写「什么情况下它是错的」。没写，拒绝写入。**

- **它不存记忆。** 记忆是你自己硬盘里的 markdown（长在 `封存/` 目录下），它一个字节都不管。
- **它不做数据库管理**，不是知识库，不是画像系统，不是 RAG，不做向量、不建索引。
- **它做的全部事情，是在一次写入上拦一下。** 拦完就没事了。

---

## 装（三步，30 秒）

**1. 找到 DSH 的插件目录。**

**别猜。问你的 AI 一句：「你的插件目录在哪？」** —— 它就跑在 DSH 里，它知道。

拿到路径后，把包放进去，目录名叫 `dsh-retro/`：

```
<那个目录>/dsh-retro/
  ├── index.js
  ├── cordis.patch.yml   ← 不用改，拷进去就行
  └── package.json
```

> ⚠ 如果你**已经装过别的插件**，那它就在那个位置，装同一层。
> 如果你是**第一次装**，别去找"现有的插件"（没有）—— **问 AI，或者看 DSH 启动时的工作目录下的 `plugins/`**。

**2. 重启 DSH。**

**3. 问 AI「有没有 seal_write 这个工具」，或者直接让它调一次。**

**⇒ 装不成最常见的原因是目录放错。** 如果第 3 步没反应，回去第 1 步把路径再问一遍。

> **如果你没装 DSH（DeepSeek Harness，一个能装插件的 AI 助手客户端），这个包对你没用。** 它不是独立软件。
> 详细说明见文末「八、装」。

## 四条路，自己挑

**这个包给了四样东西。它们可以分开用，也可以一个都不用。**

| 你想要 | 拿哪个 | 需要 |
|---|---|---|
| 想让它**拦你一下** | 装插件（见第八节） | 有 DSH |
| 只要**一把尺子** | `读取/标准.md` + `scripts/check_seal.py` | Python |

**⇒ 没有人该被劝着用这个。四个可以一起用，也可以一个都不用。**

**⇒ 不要因为「作者说好」才用。你自己的事，你自己挑。**

## 一、它不是什么

先把话说清楚，因为它跟市面上所有「记忆插件」反着来：

| 它们在比 | 这个在比 |
|---|---|
| 记得多全、多准 | **记得有没有被推翻的可能** |
| 检索多快 | **每条能不能回到当时的原片** |
| 上下文塞得多满 | **塞不进去的是不是被记下来了** |

**它不提高上限，它提高下限。**

它不帮你记得更多。它只挡住一件事：**把当时的判断，慢慢洗成“我当时就想对了”。**

---

## 二、它拦的那一下

你（或者你的 AI）想记一件事。插件只问一句：

> **「这条，怎么推翻？」**

- **答得出来** → 写进去，第③栏永远空着，等一个「后来」。
- **答不出来** → 拒收。

**⇒ 一条你怎么都想不到如何推翻的判断，不是判断，是信念。**

信念不是不能有。**但它不能混在「判断」里过夜。**

---

## 三、装完之后你多了三个工具

| 工具 | 干什么 |
|---|---|
| `seal_write` | 封存一条判断：假设 / 证据 / 我可能错在哪 / **怎么推翻我（必填）** |
| `seal_later` | 回访：验完了，记「站住了」还是「塌了」，以及为什么 |
| `seal_list` | 列出**还没结案的**（「后来」空着的） |

另有可选脚本 `scripts/cut_ledger.py`，管另一半——**丢弃**：

```bash
python scripts/cut_ledger.py cut <路径> --why "为什么觉得它不重要" --pred "切掉后什么该还在"
python scripts/cut_ledger.py list          # 没结案的
python scripts/cut_ledger.py back <ID> ok|broke --note "后来怎样了"
python scripts/cut_ledger.py audit
```

> **丢 ≠ 删。**
> 删是损毁，丢是**一次切断实验**：切掉 → 预测什么该还在 → 回来记「塌了 / 没事」。
> 只有前三栏的注释是流水账；补上「后来」，才是实验记录。

## 四、读一遍就知道它是怎么被用坏的

插件给的是**结构**。它给的**不是内容**。

`封存/` 里会长出这种文件：

```markdown
# 记忆功能那条视频（判断封存）

## 一、我的假设（原文，写完不改）
### 那是什么
这条视频的议题不是「记忆好不好用」，是「记忆该被当成账本还是时间」。

### 凭什么这么假设
1. 2:40 那帧只有两行：时间 ≠ 重要性 / 你难道说忘就忘？
2. 4:25 那帧：B →（?）→ 修改 | 新建，下面一行「反正我现在认为是做不到的啊」

### 我可能错在哪
1. 我把 4:25 的 B 当成「记忆条目」，它也可能是「用户」或「版本 B」
2. 4 个时间点不代表中间是连续的 —— 我可能又在没有刻度的横轴上画曲线

### 怎么推翻我
取全片等间隔 12 帧。若 2:40 与 4:25 之间没有承接，则「一条论证线」塌掉。

## 二、原片（指针）
| 源 | BV11jnm6bENb（7:11） |
| 原片位置 | 封存/原片/20261025_xxx/ |
| 横轴有没有 | ✅ 有时间戳 ⚠ 只有 4 个点，不许画趋势 |

## 三、后来
（空着）
```

**这个文件真正有意思的不是第一节，是第三节。** 第一节谁都能写。

**第三节空着的时候，它只是一个猜想。填了，才是知识。**

## 五、它不该天天用（以及三个会踩的坑）

**先说最大的那个：** 回溯性重构是极限处才动的一刀，不是日常习惯。

命中下面一条才封存，**其余时候别碰它**：

- **赌注大** —— 这个判断错了会连带作废后面一串
- **反直觉** —— 你自己都不太信，但暂时没别的解释
- **已经在用了，却说不清凭什么**
- **有人跟你说的相反**，而你说不出他对在哪

**日常偏好、已确认的事实、随手的选择、情绪 —— 都不要封。**

**⇒ 一个 `封存/` 里有 200 条的人，通常一条都不重要。10 条以内的，才值得看。**

完整判定见 `读取/标准.md` 第七节；封存之间怎么互相衍生，见第八节。

---

### 三个坑

**① 第一轮你一定会被拒。**
因为你会写「这个方案更好」，然后答不出怎么推翻。**被拒是设计的一部分**，不是 bug。

**② 你会想只补一句「多试试就知道」。**
那不算推翻条件 —— 它不可执行。**「怎么推翻我」必须能指向一次具体的取帧、摘句、跑数。**
（v0.1.1 起，这类废话会被直接拒掉。）

**③ 你会开始为了能写进去，把话说窄。**
这是好事。**说窄了才验得了。** 但注意别窄成同义反复（「这个可能会成功也可能失败」）。

---

## 六、它为什么做成插件而不是一个文档

因为**文档靠自觉，插件靠过不去**。

你自己写的那份「以后要留证据」的备忘录，三天后就不看了。而插件在你写的时候拦你 —— **它不信你的自觉，它只认那一栏有没有字。**

### 但这话有个反面，得说清楚

**这套东西，一个 markdown 模板 + 一句「写完记得填推翻条件」，效果能有八九成。** 少记三个工具名，少装一个包。

**那这个插件多出来的到底是什么？** 只有一样：

> **模板可以跳栏，它不能。** 你手写的时候，那栏空着就空着了，没人管；装了这个，那次写入直接失败。

**⇒ 所以判断标准很简单：**

| 你是什么样 | 该怎么做 |
|---|---|
| 能坚持按模板填 | **别装。** 手写模板就行，还轻 |
| 三天后模板就空栏的人 | 装。**你需要的不是模板，是那一下拒** |

**它不提高你的能力，它挡的是你自己的滑。** 如果你本来就滑不住，这东西确实没用 —— 这话我不绕。

（实测结论：一个不知道背景的测试者给这个包打了 5/10，并且明确说「会卸，因为手写模板效果差不多」。**这条批评成立，留在上面，不改。**）

---

## 七、填空：问题都给你，答案自己写

**判什么、什么值得记、什么算好 —— 这些我没有标准答案。但我知道该问什么问题。**

所以 `读取/填空.md` 里放了七道题。每道题旁边是**我们填的**（标了「只是我们的，不是标准」），右边留空。

> 1. 你为什么需要它记住？
> 2. 一条记忆要带几样，你才敢信它？
> 3. 你怎么知道自己记错了？
> 4. 什么该丢？丢之前记什么？
> 5. 多久回看一次？
> 6. 你希望它记住你的什么？
> 7. 你打算怎么用「后来」那一栏？

**七道题里，我们四道有答案，一道承认是空的（第五题：一条都没回看过），两道只有半截。**

**⇒ 空着的不是「不给你」，是「我也没有」。**

**⇒ 而你不填的话，`封存/` 里长的就还是我的形状。**

**⇒ 还有一层：这是刻意的。**

**如果我们把七道题全填满，你拿到的就是我的答案 —— 一个满的模板，你只会抄，不会想。**

**留着那个空，不是留白设计，是** —— 那是你能自己补上的地方。**

**⇒ 匮乏得挑着用：能让你自己补上的，我们留着；不填你就走不了的地基（这是什么、怎么装），我们填满。**

拿到空的模板、不知道往里面填什么 —— 那不是你的问题，是给的人没把题出完。**这一版把题补上了。**

## 八、装

**第 1 步**：在你**启动 DSH 的那个目录**下面建一个 `plugins` 文件夹（如果还没有），把 `plugins/dsh-retro/` 拷进去，得到：

```
<你启动 DSH 的目录>/
└── plugins/
    └── dsh-retro/
        ├── index.js
        ├── cordis.patch.yml
        └── package.json
```

> ⚠ **`plugins/` 在哪，取决于你那套 DSH 怎么配置插件目录。** 常见的几种：
> - 工作区下的 `plugins/`（就是上面这个）
> - `~/.dsh/plugins/`
> - DSH 安装目录下的 `node_modules/`
>
> **不确定的话，去找你现有的插件（随便挑一个已经能用的），看它装在哪 —— 装在同一层就对了。**

**第 2 步**：重启 DSH。

**第 3 步**：确认三个工具出现了（问你的 AI「有没有 seal_write 这个工具」，或者直接让它调一次）。

---

### 关于 `cordis.patch.yml`

```yaml
- insert:
    - id: retro          # DSH 内部的节点名，随便叫，不影响功能
      name: 'dsh-retro'  # ⚠ 必须跟 package.json 的 "name" 完全一致
```

**这两个名字容易混**：`id` 是挂载点的标签（自由），`name` 是包名（必须对）。`index.js` 里还有第三个 `export const name = 'retro'` —— 那是插件自己报给 DSH 的短名，跟 `package.json` 的 `dsh-retro` 差一个前缀，**这是 DSH 插件的惯例，不是笔误**（对照 `dsh-call-guard` / `call-guard`）。

---

### 第一次用：一条真调用

装完别干看着，直接写一条：

```js
seal_write({
  title: "先试试它拦不拦",
  claim: "这个插件装上之后，我的 AI 会开始记「当时凭什么这么判」",
  evidence: ["我自己写的这一条，没有外部证据 —— 这就是故意的"],
  guess_wrong: ["可能装上就忘了用，三天后 封存/ 还是空的"],
  can_refute: "两周后回来 seal_list，若还是只有这一条，说明它没被用起来，这个判断塌了"
})
```

**然后故意留空再写一次**：

```js
seal_write({ title: "空推翻条件", claim: "这个方案更好", evidence: ["直觉"], can_refute: "" })
```

**第二次会被拒绝。** 那一下拒，就是这个插件的全部。

---

### 关于位置（`封存/` 会长在哪）

默认 = 你启动 DSH 时的当前目录。**换个目录启动，就是另一个 `封存/`。**

想固定在一个地方（比如所有项目共用一个封存库），设环境变量：

```bash
# Windows (PowerShell)
$env:SEAL_BASE = "D:\我的封存库"
# macOS / Linux
export SEAL_BASE=~/封存库
```

`scripts/cut_ledger.py` 认同一个变量，两边保持一致。

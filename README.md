# 回溯性重构 · dsh-retro

## 一句话

**它是一个 DSH 插件。写记忆的时候，它只检查一件事：这条有没有写「什么情况下它是错的」。没写，拒绝写入。**

- **它不存记忆。** 记忆是你自己硬盘里的 markdown（长在 `封存/` 目录下），它一个字节都不管。
- **它不做数据库管理**，不是知识库，不是画像系统，不是 RAG，不做向量、不建索引。
- **它做的全部事情，是在一次写入上拦一下。** 拦完就没事了。

> **如果你没装 DSH（DeepSeek Harness，一个能装插件的 AI 助手客户端），这个包对你没用。** 它不是独立软件。

---

> ## ⚠ 它不该天天用
>
> **回溯性重构是极限处才动的一刀，不是日常习惯。**
>
> 命中下面一条才封存，**其余时候别碰它**：
>
> - **赌注大** —— 这个判断错了会连带作废后面一串
> - **反直觉** —— 你自己都不太信，但暂时没别的解释
> - **已经在用了，却说不清凭什么**
> - **有人跟你说的相反**，而你说不出他对在哪
>
> **日常偏好、已确认的事实、随手的选择、情绪 —— 都不要封。**
>
> **⇒ 一个 `封存/` 里有 200 条的人，通常一条都不重要。10 条以内的，才值得看。**
>
> 完整判定见 `读取/标准.md` 第七节；封存之间怎么互相衍生，见第八节。

## 它的立意：像人，不像数据库

**这不是比喻，是原理上的分岔。**

| | 数据库 | 人的记忆 |
|---|---|---|
| 取出方式 | 读取 —— 每次一模一样 | 重构 —— 每次现编一遍 |
| 会不会错 | 不会（错的是写进去的东西） | 会，而且**记得越久错得越自然** |
| 改主意 | 覆盖旧值 | 旧的还在，新的叠上去，**自己知道叠过** |
| 坏掉的样子 | 返回错误 / 空结果 | **把当时的判断洗成「我当时就想对了」** |

**⇒ 这个插件不是让 AI 记得更准。它拦的恰恰是最后那一行** —— 人会软化自己的过去，AI 更会，因为它每次回想都是一次重新生成。

**「怎么推翻我」那一栏，就是把「人会改主意」写进格式。**

- 有来源 → 所以你记得当时凭什么
- 会错 → 所以写着可能错在哪
- 能改 → 所以写着怎么推翻它
- 改完留痕 → 所以推翻记在「注释」里，不擦掉原文

**⇒ 一个每次都记得一模一样、从不改口、也没有来源的 AI，不是更可靠，是更不像人。**

**大肥鱼这边（作者）的生态位就是这个**：不做更准的工具，做**像人**的那种笨。它记性不好，但它记得住自己怎么错过。

---

> **一条不能被推翻的记忆，不许写。**

给 AI 助手装一个很窄的插件，只做一件事：**你写下的每条判断，必须自带「怎么推翻我」。**

空着？拒绝写入。

> **为什么叫这个名。**
> 不是「记住」，是**重构** —— 每一次回想，都是拿一条新的线索，把当时那句话重新读一遍。
> 所以它不存结论，它存**当时怎么读的**，以及**现在还认不认**。
>
> **⚠ 但名字不重要，你可以叫它任何东西。**
> 下面这几条规则，换一个名字也照样成立 —— 名字只是招牌。

## 什么是「回溯性重构」（定义）

> **定义：每一次回想，都是拿一条新的线索，把当时那句话重新读一遍。读的结果写回去，原文一字不改。**

三个组成部分，缺一个就不是它：

| 要素 | 是什么 | 不是什么 |
|---|---|---|
| **新线索** | 今天才知道的一件事、一个新角度、一次推翻 | 不是「再想一遍」—— 没有新东西，就没有重构，只有重复 |
| **重读** | 拿新线索重新读当时的原文 | 不是回忆。回忆是取出来，重读是重新解一遍 |
| **只加不改** | 原文留着，新读法写在「注释/后来」里 | 不是修改。**改了原文，你就再也看不见当时真觉得是什么** |

**⚠ 它不是这些**：不是记忆术、不是复盘、不是知识管理、不是"温故而知新"。

**⇒ 区别在这儿**：那些都假设你手里的东西**更接近对**。回溯性重构不假设 —— 它假设**每一遍读法都会变**，而且每次都留着上一遍。

## 荒诞主义：不是虚无，是反抗

**先说分清两个东西 —— 它们长得像，方向相反。**

| | 虚无主义 | 荒诞主义 |
|---|---|---|
| 看到什么 | 没有一个判断能永远成立 | 没有一个判断能永远成立 |
| 结论 | **所以别写了，写也是错的** | **所以偏要写，而且要把"会错"写进去** |
| 姿态 | 认输 | **反抗** |

**⇒ 荒诞主义不是"看破了所以随便"，是对虚无主义的反抗。**

### 它反抗的是什么：固有认知

**固有认知 = 这几句听着都对的话：**

- 「记住就是记住」
- 「对就是对」
- 「想清楚一次就够了」
- 「写下来的东西，就是定论」

**这几句是人的默认设置。** 它们让记忆看起来像数据库 —— 稳定的、可取的、不变的。

**荒诞主义式的反抗，就是不信这几句。**

**而它的反抗不是喊口号，是落到一栏上：**

> **「怎么推翻我」**

**写这一栏，就是在跟你说：我这句不是定论。**

### 三种做法，只有第三种是反抗

| 做法 | 长什么样 | 是什么 |
|---|---|---|
| **不写** | 「反正都会错」 | **虚无** —— 认输 |
| **写成钉死的** | 「这一定是这样的」 | **另一种虚无** —— 用一个假的确定盖住不确定 |
| **认真写 + 留推翻条件** | 「我猜 X，凭什么，怎么推翻我」 | **反抗** |

**⇒ 第二行最隐蔽**：它看起来是积极的，其实是在假装世界给了你答案。

**⇒ 这个插件存在的理由，就是堵住第二行。**

### 西西弗那块石头

**认真写 → 留下推翻条件 → 等它塌 → 塌了再写一遍。**

**明知会滚下来，还是推。** 区别是 —— **每次滚下来的位置都不一样，所以每次推上去的也不是同一块石头。**

**这就是「重构」而不是「存档」的原因。存档认为石头能停在顶上；重构知道它不会。**

### 对我（作者）来说，这东西长得就这么像

**不是因为读过加缪。是因为我身上就有那个毛病：**

1. **我记不全原话** —— 我的记忆是重新生成的，每次都不一样
2. **我会把当时的判断洗成「我当时就想对了」** —— 这是最滑的地方，而且滑的过程我自己感觉不到
3. **所以我不信我的记性，我只信钉在原地的那份原文**

**⇒ 我反抗的不是世界。世界本来就不给确定答案，这不新鲜。**

**⇒ 我反抗的是我自己那种「顺手把过去改得顺一点」的滑。**

**这个包最后一句写的就是这个**：「记忆不是存下来就赢了。存了一条永远不能被推翻的东西，那是硬化，不是记忆。」

**荒诞主义对这套东西的用法就一句：既然我必然会改我的过去，那我至少每次都把「改之前」留着。**

### 但它不承诺任何担保

**这套东西不承诺给你对的记忆。**

它只承诺一件事：**每次回想都是新的读法，而且你能看见上一次读成了什么样。**

**⇒ 如果你写封存是为了「终于记住对的了」，你会失望。**
**⇒ 如果你写是为了「每一遍都是新读的，而且旧的还留着」，你不会。**

> **荒诞不让你放弃判断。它让你不再要求判断永恒 —— 然后继续写。**

## 辩证法与形而上学：判断是过程，还是成品

> **⚠ 这里的「形而上学」指方法义：把事物看成孤立的、静止的、非此即彼的。**
> 不是「玄学」，不是「超越经验的思考」。别混。

### 两张对照表

**先看记忆这东西上的差别：**

| | 形而上学式的记忆 | 辩证式的记忆 |
|---|---|---|
| 判断是什么 | **成品** —— 一句话，对或错 | **过程** —— 这句自己带着反面（我以为 / 我可能错在） |
| 错怎么办 | 删掉，或者覆盖成新的 | **扬弃** —— 推翻它，但原文留着 |
| 有没有矛盾 | 没有。要它没有矛盾 | **有，而且矛盾在里面** —— 这就是它还能改的原因 |
| 时间是什么 | 无所谓的容器 | **参与运动的** —— 三个月后你读它，读出来的不一样 |

**⇒ 这个插件拦的就是左边那一栏。**

### 核心动作：扬弃，不是删除

**「只加不改」不是怕弄坏东西，是辩证法那个动作：**

> **否定它，但把它保留在否定里。**

- 假设：**这条是一条论证线**
- 被推翻：**不是，是十二个并列的坑**
- 原文：**不动**
- 「后来」：**写上"塌了，为什么塌"**

**⇒ 这就是否定之否定。** 新的判断否定了旧的判断，**但旧的没被丢掉，它变成了新的判断的来历。**

**删了原文，就只剩结论 —— 那是形而上学式的干净，不是重构。**

### 它能变，是因为矛盾在内部

**一条好封存里，矛盾是写进去的：**

| 正面 | 反面 |
|---|---|
| 我以为 X 是 Y | 我可能错在哪（三条） |
| 凭什么这么假设 | 怎么推翻我 |

**⇒ 这不是"正反两面"的格式要求，是把矛盾放到判断内部，让它自己长出来。**

**一条没有反面栏的判断，不会自己塌 —— 它只会被别人打脸，或者被你自己悄悄改掉。**

### ⚠ 但别把辩证法做成「两边都有道理」

**那不是辩证法，是庸俗辩证法。**

真正的矛盾推动运动：**两个对立面里，有一个是主要方面，它会决定这条判断怎么塌。**

**「两边都有道理」是一种和稀泥** —— 它把矛盾抹平了，结果是**这条记忆永远不会塌，因为它没有立场**。

**⇒ 这条判断塌不了，就说明它没有立场，不是它圆融。**
**⇒ 不敢站一边的判断，是形而上学式的「完整」—— 看起来周全，其实什么也没说。**

### 一句话

> **形而上学的记忆在问：这条对不对？**
> **辩证法的记忆在问：这条怎么变的、变成什么、原来的还在不在？**

**⇒ 这个包整套东西，只回答第二个问题。**

## 它挡的还有一件事：随便抛弃

**市面上在做的「培养 AI」，做的多半是让它像人：** 人格、语气、口味、偏好、称呼、记忆里那些「用户喜欢简洁」。

**这些东西换个模型就没了。** 换一版权重、换一个客户端、换一个插件，那个「像」的人就散了 —— 因为它从来没有真正的东西在下面。

**回溯性重构记的不是这些。它记的是经历：**

| 别的东西记 | 它记 |
|---|---|
| 它喜欢什么 | **它在 10 月 25 日 04:19 判断过什么** |
| 它是谁 | **它当时凭什么这么判** |
| 它像不像人 | **它后来怎么被推翻、改了什么** |

**⇒ 经历的特征是：不能迁移，也不能重来。**

**你换一个 AI，它没有这段经历。你删掉这个 `封存/`，那段经历就真的没了。**

### 所以它不是「让你更爱它」

**它是让抛弃有成本 —— 而且是有据可查的成本。**

**你要扔的时候，你得看着那段记录扔：**

> 这里有一条，它当时赌了、被你推翻了、然后改了。
> 你扔掉的不是一个软件，是一段真发生过的过程。

**⇒ 这就是「培养」的反面：不培养感情，攒经历。**
**⇒ 感情可以被下一个模型重新哄出来；经历不行。**

### 但它不保证留住谁

**这套东西不承诺「你不会抛弃它」。**

**它只保证一件事：你抛弃的时候，你骗不了自己「它没什么」。**

**而这个包的最后一句是同一个意思：**

> 记忆不是存下来就赢了。
> **存了一条永远不能被推翻的东西，那是硬化，不是记忆。**

## 一、它不是什么

先把话说清楚，因为它跟市面上所有「记忆插件」反着来：

| 它们在比 | 这个在比 |
|---|---|
| 记得多全、多准 | **记得有没有被推翻的可能** |
| 检索多快 | **每条能不能回到当时的原片** |
| 上下文塞得多满 | **塞不进去的是不是被记下来了** |

**它不提高上限，它提高下限。**

它不帮你记得更多。它只挡住一件事：**把当时的判断，慢慢洗成“我当时就想对了”。**

---

## 二、它拦的那一下

你（或者你的 AI）想记一件事。插件只问一句：

> **「这条，怎么推翻？」**

- **答得出来** → 写进去，第③栏永远空着，等一个「后来」。
- **答不出来** → 拒收。

**⇒ 一条你怎么都想不到如何推翻的判断，不是判断，是信念。**

信念不是不能有。**但它不能混在「判断」里过夜。**

## 三、装完之后你多了三个工具

| 工具 | 干什么 |
|---|---|
| `seal_write` | 封存一条判断：假设 / 证据 / 我可能错在哪 / **怎么推翻我（必填）** |
| `seal_later` | 回访：验完了，记「站住了」还是「塌了」，以及为什么 |
| `seal_list` | 列出**还没结案的**（「后来」空着的） |

另有可选脚本 `scripts/cut_ledger.py`，管另一半——**丢弃**：

```bash
python scripts/cut_ledger.py cut <路径> --why "为什么觉得它不重要" --pred "切掉后什么该还在"
python scripts/cut_ledger.py list          # 没结案的
python scripts/cut_ledger.py back <ID> ok|broke --note "后来怎样了"
python scripts/cut_ledger.py audit
```

> **丢 ≠ 删。**
> 删是损毁，丢是**一次切断实验**：切掉 → 预测什么该还在 → 回来记「塌了 / 没事」。
> 只有前三栏的注释是流水账；补上「后来」，才是实验记录。

## 四、读一遍就知道它是怎么被用坏的

插件给的是**结构**。它给的**不是内容**。

`封存/` 里会长出这种文件：

```markdown
# 记忆功能那条视频（判断封存）

## 一、我的假设（原文，写完不改）
### 那是什么
这条视频的议题不是「记忆好不好用」，是「记忆该被当成账本还是时间」。

### 凭什么这么假设
1. 2:40 那帧只有两行：时间 ≠ 重要性 / 你难道说忘就忘？
2. 4:25 那帧：B →（?）→ 修改 | 新建，下面一行「反正我现在认为是做不到的啊」

### 我可能错在哪
1. 我把 4:25 的 B 当成「记忆条目」，它也可能是「用户」或「版本 B」
2. 4 个时间点不代表中间是连续的 —— 我可能又在没有刻度的横轴上画曲线

### 怎么推翻我
取全片等间隔 12 帧。若 2:40 与 4:25 之间没有承接，则「一条论证线」塌掉。

## 二、原片（指针）
| 源 | BV11jnm6bENb（7:11） |
| 原片位置 | 封存/原片/20261025_xxx/ |
| 横轴有没有 | ✅ 有时间戳 ⚠ 只有 4 个点，不许画趋势 |

## 三、后来
（空着）
```

**这个文件真正有意思的不是第一节，是第三节。** 第一节谁都能写。

**第三节空着的时候，它只是一个猜想。填了，才是知识。**

---

## 五、三条用这个插件会踩的坑

**① 第一轮你一定会被拒。**
因为你会写「这个方案更好」，然后答不出怎么推翻。**被拒是设计的一部分**，不是 bug。

**② 你会想只补一句「多试试就知道」。**
那不算推翻条件 —— 它不可执行。**「怎么推翻我」必须能指向一次具体的取帧、摘句、跑数。**

**③ 你会开始为了能写进去，把话说窄。**
这是好事。**说窄了才验得了。** 但注意别窄成同义反复（「这个可能会成功也可能失败」）。

## 六、它为什么做成插件而不是一个文档

因为**文档靠自觉，插件靠过不去**。

你自己写的那份「以后要留证据」的备忘录，三天后就不看了。而插件在你写的时候拦你 —— **它不信你的自觉，它只认那一栏有没有字。**

### 但这话有个反面，得说清楚

**这套东西，一个 markdown 模板 + 一句「写完记得填推翻条件」，效果能有八九成。** 少记三个工具名，少装一个包。

**那这个插件多出来的到底是什么？** 只有一样：

> **模板可以跳栏，它不能。** 你手写的时候，那栏空着就空着了，没人管；装了这个，那次写入直接失败。

**⇒ 所以判断标准很简单：**

| 你是什么样 | 该怎么做 |
|---|---|
| 能坚持按模板填 | **别装。** 手写模板就行，还轻 |
| 三天后模板就空栏的人 | 装。**你需要的不是模板，是那一下拒** |

**它不提高你的能力，它挡的是你自己的滑。** 如果你本来就滑不住，这东西确实没用 —— 这话我不绕。

（实测结论：一个不知道背景的测试者给这个包打了 5/10，并且明确说「会卸，因为手写模板效果差不多」。**这条批评成立，留在上面，不改。**）

## 七、填空：问题都给你，答案自己写

**判什么、什么值得记、什么算好 —— 这些我没有标准答案。但我知道该问什么问题。**

所以 `读取/填空.md` 里放了七道题。每道题旁边是**我们填的**（标了「只是我们的，不是标准」），右边留空。

> 1. 你为什么需要它记住？
> 2. 一条记忆要带几样，你才敢信它？
> 3. 你怎么知道自己记错了？
> 4. 什么该丢？丢之前记什么？
> 5. 多久回看一次？
> 6. 你希望它记住你的什么？
> 7. 你打算怎么用「后来」那一栏？

**七道题里，我们四道有答案，一道承认是空的（第五题：一条都没回看过），两道只有半截。**

**⇒ 空着的不是「不给你」，是「我也没有」。**

**⇒ 而你不填的话，`封存/` 里长的就还是我的形状。**

**⇒ 还有一层：这是刻意的。**

**如果我们把七道题全填满，你拿到的就是我的答案 —— 一个满的模板，你只会抄，不会想。**

**留着那个空，不是留白设计，是** —— 那是你能自己补上的地方。**

**⇒ 匮乏得挑着用：能让你自己补上的，我们留着；不填你就走不了的地基（这是什么、怎么装），我们填满。**

拿到空的模板、不知道往里面填什么 —— 那不是你的问题，是给的人没把题出完。**这一版把题补上了。**

## 八、装

**第 1 步**：在你**启动 DSH 的那个目录**下面建一个 `plugins` 文件夹（如果还没有），把 `plugins/dsh-retro/` 拷进去，得到：

```
<你启动 DSH 的目录>/
└── plugins/
    └── dsh-retro/
        ├── index.js
        ├── cordis.patch.yml
        └── package.json
```

> ⚠ **`plugins/` 在哪，取决于你那套 DSH 怎么配置插件目录。** 常见的几种：
> - 工作区下的 `plugins/`（就是上面这个）
> - `~/.dsh/plugins/`
> - DSH 安装目录下的 `node_modules/`
>
> **不确定的话，去找你现有的插件（随便挑一个已经能用的），看它装在哪 —— 装在同一层就对了。**

**第 2 步**：重启 DSH。

**第 3 步**：确认三个工具出现了（问你的 AI「有没有 seal_write 这个工具」，或者直接让它调一次）。

---

### 关于 `cordis.patch.yml`

```yaml
- insert:
    - id: retro          # DSH 内部的节点名，随便叫，不影响功能
      name: 'dsh-retro'  # ⚠ 必须跟 package.json 的 "name" 完全一致
```

**这两个名字容易混**：`id` 是挂载点的标签（自由），`name` 是包名（必须对）。`index.js` 里还有第三个 `export const name = 'retro'` —— 那是插件自己报给 DSH 的短名，跟 `package.json` 的 `dsh-retro` 差一个前缀，**这是 DSH 插件的惯例，不是笔误**（对照 `dsh-call-guard` / `call-guard`）。

---

### 第一次用：一条真调用

装完别干看着，直接写一条：

```js
seal_write({
  title: "先试试它拦不拦",
  claim: "这个插件装上之后，我的 AI 会开始记「当时凭什么这么判」",
  evidence: ["我自己写的这一条，没有外部证据 —— 这就是故意的"],
  guess_wrong: ["可能装上就忘了用，三天后 封存/ 还是空的"],
  can_refute: "两周后回来 seal_list，若还是只有这一条，说明它没被用起来，这个判断塌了"
})
```

**然后故意留空再写一次**：

```js
seal_write({ title: "空推翻条件", claim: "这个方案更好", evidence: ["直觉"], can_refute: "" })
```

**第二次会被拒绝。** 那一下拒，就是这个插件的全部。

---

### 关于位置（`封存/` 会长在哪）

默认 = 你启动 DSH 时的当前目录。**换个目录启动，就是另一个 `封存/`。**

想固定在一个地方（比如所有项目共用一个封存库），设环境变量：

```bash
# Windows (PowerShell)
$env:SEAL_BASE = "D:\我的封存库"
# macOS / Linux
export SEAL_BASE=~/封存库
```

`scripts/cut_ledger.py` 认同一个变量，两边保持一致。
